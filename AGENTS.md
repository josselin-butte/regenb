- Serve uploaded site photography through Lovable Assets pointer imports using the published asset origin, because repository binaries add unnecessary weight and local Vite does not proxy asset paths.
- Research notebook entries are Markdown files with YAML frontmatter in src/content/carnet/ (one file per language; an English file sets `lang: en`, its own `slug`, and `fr: <french-slug>` to link them), auto-loaded by src/lib/carnet.ts, so publishing a note needs no code change.
- Public pages: French at the root, English under /en, language derived from the URL only via src/lib/routes.ts, because each language needs its own crawlable URLs.
- Generate an early production Content-Security-Policy through Vite that allows application bundles, exact consent-gated Meta SDK/config paths, and only the consent-gated Continuo Substack embed as a frame; narrow allowlists block unapproved integrations before execution.
- Every cookie/storage entry the site can set is declared in src/lib/trackers.ts, which renders the /cookies table, so the disclosure stays in sync with the code.
- Manage consent centrally via src/lib/consent.ts and the app-level ConsentProvider; optional integrations use registerOptionalService with synchronous teardown and declared cookie cleanup, because withdrawal must stop services before reloading. Meta PageView uses advertising consent; the Continuo Substack frame uses external-content consent. New integrations require cookie disclosures, narrowly scoped CSP, and a CONSENT_VERSION bump.
- Render notice, privacy and terms as separate route-selected Legal pages with shared layout and a shared English translation notice also used by Cookies; legacy legal routes use a replace redirect (including legacy section hashes), because existing links must stay usable without duplicate indexable legal pages.
- Website forms post to the forward-to-crm backend function, which maps entries to the CRM intake format and adds the intake secret server-side, because the secret must never reach the browser and contacts live only in the CRM project.

- Install the browser Pixel through the app-level MetaPixel lifecycle into document.head, without a noscript beacon or server reporting, because every public route must respect the central advertising choice.
- Load the official Continuo iframe through registerOptionalService under external-content consent, with synchronous frame removal on withdrawal; do not infer subscription success or dispatch Lead from cross-origin frame activity.
